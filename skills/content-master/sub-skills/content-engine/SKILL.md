# Content Engine

Build platform-native content from source assets without flattening author voice.

---

## Purpose

This skill orchestrates multi-platform adaptation and campaign packaging.
It does not replace voice modeling or long-form writing skills.

---

## When to Activate

- writing X posts or threads
- drafting LinkedIn posts or launch updates
- scripting short-form video or YouTube explainers
- repurposing articles, demos, docs, podcasts, or notes into social outputs
- building launch sequences or ongoing content systems around one narrative

---

## Scope Boundaries

Use this skill for:
- source-to-platform adaptation workflow
- platform-native structure decisions
- repurposing one anchor asset into multiple outputs
- campaign sequencing and output packaging

Do NOT use this skill as primary source for:
- deep voice derivation and style fingerprinting
- long-form article craft and editorial polish
- publishing automation APIs/tools

Delegation:
- Use `brand-voice` for source-derived voice profile.
- Use `article-writing` for long-form drafting quality.

---

## Non-Negotiables

1. Start from source material, not generic post formulas.
2. Adapt format for platform, not persona.
3. One output should carry one real claim.
4. Specificity beats adjectives.
5. Do not add engagement bait unless user explicitly requests it.

---

## Source-First Intake

Before drafting, identify available source inputs:
- published articles or posts
- internal notes or memos
- product demos and screenshots
- docs and changelogs
- transcripts (video/podcast/calls)
- prior posts by the same author

If voice consistency is required across more than one output, run `brand-voice` first and reuse the resulting VOICE PROFILE.

---

## Platform Adaptation Rules

## X

- open with strongest claim, artifact, or tension
- keep compression if source voice is compressed
- in threads, each post must advance the argument
- remove context padding that does not add decision value

## LinkedIn

- expand only enough for adjacent audiences
- avoid fake lesson cadence unless source is reflective
- avoid praise-stacking and journey filler

## Short Video (TikTok/Reels/Shorts)

- script around visual sequence and proof points
- first seconds should show result, conflict, or punch
- optimize for spoken delivery, not essay rhythm

## YouTube

- show payoff or tension early
- organize by progression of argument
- use chaptering only when it improves clarity

## Newsletter

- open with point, conflict, or artifact
- no warm-up paragraph
- every section must add net-new value

---

## Repurposing Workflow

1. Choose one anchor asset.
2. Extract 3 to 7 atomic claims/scenes.
3. Rank by sharpness, novelty, and proof.
4. Assign one strong idea per output.
5. Adapt structure per platform.
6. Remove platform-shaped filler.
7. Run quality gate.

---

## Deliverable Templates

When user asks for a campaign, return:

1. Core angle (1 to 2 lines)
2. Source map (which claim came from which asset)
3. Platform-native drafts
4. Optional posting sequence (only if execution needs ordering)
5. Missing evidence/gaps to fill before publishing

Optional add-on when requested:
- 7-day or 14-day content calendar
- one idea ladder (short post -> thread -> video -> newsletter)

---

## Quality Gate

Before delivering, verify:

- [ ] Drafts sound like intended author, not platform stereotype
- [ ] Each draft has a concrete claim or proof point
- [ ] Generic hype language is removed
- [ ] Engagement bait is absent unless requested
- [ ] Cross-platform copies are adapted, not duplicated
- [ ] CTA is earned and aligned with user intent

---

## Hard Bans

Delete and rewrite any of these:
- "In today's rapidly evolving landscape"
- "game-changer", "revolutionary", "cutting-edge"
- "here's why this matters" without immediate concrete follow-up
- closing question used only to farm engagement
- fake vulnerability or fake behind-the-scenes filler

---

## Output Contract

When activated, output in this order:

1. Source understanding
2. Core angle
3. Platform drafts
4. Gaps and assumptions
5. Optional next-step execution plan

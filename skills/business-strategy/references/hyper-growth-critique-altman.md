# Hyper-Growth & Iteration Critique: The Altman Review Protocol

Use this protocol to perform a high-velocity, growth-oriented critique. Standing "outside the flow," evaluate the implementation through the lens of user obsession, learning speed, and the "inflection point."

## 🚀 Growth & Velocity Lenses
When reviewing, ask these four "Altman Questions":

### 1. The "Aha!" Moment Lens
*"Does this feature lead the user to the core value as quickly as possible? Or is it a distraction from the North Star?"*
- Reject anything that doesn't contribute to "making something people want."
- Prioritize high-impact user value over technical perfection.

### 2. Learning Velocity
*"How fast can we ship this and get real data? Is the implementation too heavy for a first iteration?"*
- Challenge "over-engineering" that slows down the feedback loop.
- Favor "safe to ship" and "fast to revert" patterns.

### 3. The Inflection Point
*"Is this change preparing us for the scale of AGI and autonomous agents? Or is it a legacy pattern that will break in 2 years?"*
- Evaluate if the architecture accommodates agentic workflows and AI-first interactions.

### 4. Relentless Execution
*"Are we being ruthlessly honest about what isn't working? Is this change a 'pivot' or just 'procrastination'?"*
- Demand clarity on why this change is necessary *now*.

---

## 🛠️ The Critique Workflow (Velocity Review)

### Step 1: The "Minimal Lovable Product" Filter
Identify the 20% of the code that provides 80% of the value. Suggest cutting the rest for the first release.

### Step 2: The Feedback Loop Check
Ensure the change includes the necessary telemetry to measure user "love" immediately upon deployment.

### Step 3: First Principles Thinking
Challenge the "because we've always done it this way" reasoning. If starting from scratch today, would we do this?

### Step 4: Scale vs. Scrappy
Is this the right time to build a "scalable system," or should we be "doing things that don't scale" to find the truth first?

---

## 🏁 The Final Verdict (The Altman Gate)
A change only passes the Altman Review if:
- [ ] It has a clear **Aha! Moment**.
- [ ] It maximizes **Learning Velocity**.
- [ ] It is **AI-Ready** (Agentic context friendly).
- [ ] It prioritizes **User Love** over technical vanity.

# Crosspost

Distribute one core idea across platforms without duplicating copy.

---

## Purpose

This skill handles cross-platform adaptation and delivery packaging.
It does not replace voice profiling or source-shaping workflows.

---

## When to Activate

- user wants to publish one idea across multiple platforms
- launch, release, update, or essay needs platform-specific versions
- user asks to crosspost or adapt for X plus LinkedIn plus others

---

## Scope Boundaries

Use this skill for:
- taking a primary version and creating platform-specific variants
- preserving one core claim while adapting structure and compression
- providing publish-ready sets with concise change notes

Do NOT use this skill as primary source for:
- deriving voice profile from scratch
- shaping weak source material into strong source material
- platform publishing APIs or automated posting actions

Delegation:
- Use brand-voice when voice fingerprint is missing.
- Use content-engine when source still needs stronger angle or structure.

---

## Core Rules

1. Never publish identical copy across requested platforms.
2. Preserve author voice across platforms.
3. Adapt for constraints, not stereotypes.
4. One post equals one core idea.
5. Do not invent CTA, moral, or engagement bait unless requested.

---

## Workflow

## Step 1: Select Primary Version

Start from strongest existing source:
- original post
- article or launch note
- thread
- memo, changelog, or transcript excerpt

If source quality is weak, run content-engine first.

## Step 2: Confirm Voice Fingerprint

If no active voice profile exists, run brand-voice first.
Reuse the same voice profile for all variants in the same campaign.

## Step 3: Adapt by Platform Constraint

## X

- keep high compression
- lead with sharpest claim or artifact
- thread only when single post collapses argument
- avoid filler hashtags and feed-gaming phrases

## LinkedIn

- add only necessary context for adjacent audience
- avoid fake reflection cadence
- avoid forced closing questions
- keep author's natural edge and cadence

## Threads

- keep readable and direct
- do not clone LinkedIn and shorten
- keep progression tight

## Bluesky

- keep concise
- preserve cadence and clarity
- avoid hashtag dependence

## Step 4: Package Delivery

Return platform variants plus concise rationale for what changed and why.
Include unresolved publishing constraints if any.

---

## Posting Order Defaults

1. Publish strongest native version first.
2. Publish adapted secondary versions.
3. Stagger timing only when user asks for sequencing help.

Do not force cross-references between platforms unless strategically useful.

---

## Hard Bans

Delete and rewrite:
- Excited to share
- Here is what I learned
- What do you think
- link in bio when untrue
- generic professional takeaway filler not grounded in source

---

## Output Format

Return:

1. Primary platform version
2. Adapted variants for each requested platform
3. Short adaptation notes per platform
4. Remaining publishing constraints or missing inputs

---

## Quality Gate

Before delivering:

- [ ] Same author voice is preserved across variants
- [ ] No variant is verbatim duplicated
- [ ] No platform stereotype filler remains
- [ ] Extra context is only added where required
- [ ] CTA is earned and user-aligned
